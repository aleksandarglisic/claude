# 6.3 Tool-Calling Sequence (HTTP Transport)

> Regenerated in Week 5 against the actual implementation (`routes/chat.py`, `tools/`).

```mermaid
sequenceDiagram
    actor User
    participant FE as Frontend
    participant BE as POST /chat
    participant DB as Postgres (ChatSession)
    participant Ollama as Ollama (qwen3:8b)
    participant Tools as Tool Layer

    User->>FE: "Where's my package?"
    FE->>BE: POST /chat {message, session_id}
    BE->>DB: SELECT ChatSession WHERE id = session_id
    DB-->>BE: state=anonymous, transcript=[]

    BE->>Ollama: [system prompt] + [user msg] + IDENTITY_TOOLS
    Ollama-->>BE: tool_call: request_identity_info()
    BE->>Tools: handle_request_identity_info()
    Tools->>DB: state → collecting_identity
    BE->>Ollama: tool result + continue
    Ollama-->>BE: "Could you share your name, address, and phone?"
    BE-->>FE: {reply, session_state: collecting_identity}

    User->>FE: "Jane Smith, 123 Main St, +15550001234"
    FE->>BE: POST /chat {message, session_id}
    BE->>DB: load ChatSession (transcript replayed, state=collecting_identity)
    BE->>Ollama: history + [user msg] + IDENTITY_TOOLS
    Ollama-->>BE: tool_call: verify_identity(first_name, last_name, address, phone)
    BE->>Tools: handle_verify_identity(...)
    Tools->>DB: SELECT Customer WHERE fuzzy match
    DB-->>Tools: match found — customer_id=abc
    Tools->>DB: pending_customer_id=abc, state=code_sent, code=123456
    Note over Tools: [2FA CODE] printed to backend console
    Tools-->>BE: {verified: true, message: "Code sent"}
    BE->>Ollama: tool result + continue
    Ollama-->>BE: "I've sent a code to your number"
    BE-->>FE: {reply, show_modal: true, session_state: code_sent}
    FE->>User: renders CodeModal

    User->>FE: enters 123456 in modal
    FE->>BE: POST /verify-code {code: "123456", session_id}
    BE->>DB: check code, expiry, attempts
    DB-->>BE: match, not expired
    BE->>DB: state=verified, customer_id=abc, append synthetic assistant turn
    BE-->>FE: {success: true, session_state: verified}
    FE->>User: modal closes, "Identity verified ✓" badge appears

    User->>FE: "What's the status of my shipment?"
    FE->>BE: POST /chat {message, session_id}
    BE->>DB: state=verified, customer_id=abc
    Note over BE: _NO_REPLAY_TOOLS: shipment results NOT replayed from transcript
    BE->>Ollama: history + [user msg] + IDENTITY_TOOLS + SHIPMENT_TOOLS
    Ollama-->>BE: tool_call: lookup_shipments()
    BE->>Tools: handle_lookup_shipments(session)
    Note over Tools: _can_access(): state==verified ✓\nALWAYS uses session.customer_id\nnever a model-supplied ID
    Tools->>DB: SELECT shipments WHERE customer_id=abc (+ selectinload packages)
    DB-->>Tools: shipment rows with packages
    Tools-->>BE: {shipments: [...]}
    BE->>Ollama: tool result + continue
    Ollama-->>BE: "Your shipment SS-1234 is out for delivery..."
    BE->>DB: persist transcript (tool args kept, result stored)
    BE-->>FE: {reply, session_state: verified}
    FE->>User: "Your shipment SS-1234 is out for delivery..."
```

**Implementation notes:**

- History is reconstructed from `ChatSession.transcript` on every request — there is no in-memory context.
- Identity tool call results (`request_identity_info`, `send_verification_code`, `check_verification_code`) are replayed as `role: assistant + role: tool` pairs so the model retains state-transition context.
- Shipment tool results (`lookup_shipments`, `get_shipment_details`) are **not** replayed (`_NO_REPLAY_TOOLS`). The model is instructed to always re-call them, ensuring admin edits are immediately visible.
- The tool loop runs up to 5 iterations per request. The system prompt is rebuilt each iteration so state transitions are reflected in the same exchange.
- `verify_identity` arguments are redacted to `{"_redacted": True}` before transcript persistence.
