# SecureShip

AI-gated shipment customer support. Users verify their identity conversationally with a locally-run LLM before accessing their shipment data. The chat is the product — there is no traditional login for end users.

---

## What it does

A customer lands on the chat and asks about their delivery. Before the LLM shares any shipment data, it runs them through an identity verification flow:

1. Collects first name, last name, address, and phone number conversationally
2. Matches those details against the customer database (fuzzy address matching)
3. Sends a 6-digit code to the customer's phone (mocked to the backend console)
4. Verifies the code via a modal
5. Unlocks shipment data for the rest of the session — scoped to that customer only

The LLM never has direct database access. It requests tools; the backend decides whether to execute them based on session state. Prompt injection cannot bypass this because the gate lives in Python code, not the model's prompt.

A separate admin panel (Auth0-protected) lets admins manage customers, shipments, and packages. The two identity systems — conversational verification and Auth0 JWTs — never intersect.

## Quick start

```bash
# 1. Pull the model (once, on the host machine)
ollama pull qwen3:8b

# 2. (Admin panel only) Copy and fill in Auth0 credentials
cp .env.example .env
# Edit .env with AUTH0_DOMAIN, AUTH0_CLIENT_ID, AUTH0_AUDIENCE

# 3. Start the stack
cd secureship
docker-compose up

# 4. Seed mock data (first run or after wipe)
docker-compose exec backend python scripts/seed_data.py
```

| URL | Service |
|-----|---------|
| http://localhost:3000 | Chat UI |
| http://localhost:3000/admin | Admin panel (Auth0 login) |
| http://localhost:8000/docs | FastAPI OpenAPI docs |

## Architecture

See `docs/diagrams/` for full Mermaid diagrams. Summary:

**Backend** (`backend/`) — FastAPI + SQLAlchemy 2.0 async, Postgres 16. Session state lives in the `chat_sessions` table, not in memory. Every chat turn is persisted to a JSONB transcript column so page refresh restores the full conversation.

**Tool layer** (`backend/tools/`) — The LLM can only *request* tools. `_can_access()` in `tools/shipments.py` enforces the identity gate in Python code. No amount of prompt manipulation can change `session.state` or `session.customer_id`, which are set only by the verification flow.

**LLM** — Ollama (`qwen3:8b`) on the host machine, reached from Docker via `http://host.docker.internal:11434`. Runs on Apple Metal. Reasoning tokens (`<think>`) are disabled (`think: false`) for faster responses.

**Frontend** (`frontend/`) — React 18 + Vite, TypeScript. All API types and React Query hooks are generated by Orval from `/openapi.json` — nothing is hand-written. Session ID is stored in `sessionStorage` (tab-scoped).

**Admin panel** — Auth0 SPA login → RS256 JWT → `require_admin` FastAPI dependency validates against Auth0 JWKS. Full CRUD for customers, shipments, and packages. Completely separate from the chat identity system.

## Known limitations and deliberate tradeoffs

**Mock SMS.** The 6-digit verification code is printed to the backend console (`[2FA CODE] 123456`). Real Twilio SMS is a stretch goal.

**No production hardening.** CORS is locked to `localhost:3000`. There is no rate limiting beyond the 3-attempt code lockout. This is a demo/educational build.

**Frontend requires `--build` for source changes.** The frontend Docker container has no volume mount. Backend changes hot-reload automatically via uvicorn `--reload`.

**Shipment tool results are never cached in conversation history.** `lookup_shipments` and `get_shipment_details` results are excluded from transcript replay so admin edits are immediately visible in the next chat message. This means the LLM re-queries the database on every shipment question, even in the same session.

**Session timeout resets unverified sessions.** Sessions older than 24 hours that haven't reached `verified` are silently reset to `anonymous` on the next message. Verified and escalated sessions are kept indefinitely.

**`qwen3:8b` tool-calling reliability.** Smaller models (`llama3.2:3b`) have weaker tool-calling. If the model ignores tool calls, switch to `qwen3:8b` or check Ollama's tool support with `ollama show qwen3:8b`.

**Admin identity is not mirrored locally.** There is no `admin_users` table. Auth0 is the only source of truth for admin identity. `GET /admin/me` returns the JWT payload but never writes it to the database.
